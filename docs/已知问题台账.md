# 已知问题台账

> **用途**：登记「已发现、但尚未决策修改」的问题，避免每次质量审查重复发现、重复讨论、重复踩坑。
>
> **本文件存在的原因**：一次三端代码规范清理中，多项问题看似「魔术字符串」却因**同值不同域**而不可机械替换——盲目套用常量会静默改变语义。这类判断每次审查都要重新推理一遍，因此固化到本文件。

## 使用约定

| 角色 | 行为 |
|---|---|
| **quality-review** | **Step 0** 启动时先读本文件；命中已登记项（状态为 `OPEN` / `DEFERRED` / `WONTFIX`）时**不再作为新发现上报**，报告中以一行「已登记 KI-xxx」带过 |
| **quality-review** | 审查结束回写：用户决策「暂不改」→ 追加登记为 `OPEN`；用户决策「改」→ 修复后置为 `RESOLVED` |
| **人工** | 可直接编辑本文件，与 Claude 共用同一份事实 |

**匹配方式**：按「位置 + 现象」描述匹配，**不按行号**（行号会随改动漂移）。
**清理时机**：`RESOLVED` 项保留至下一次全量审查时删除。

### 状态取值

| 状态 | 含义 | 审查时行为 |
|---|---|---|
| `OPEN` | 已确认存在，尚未决策是否修改 | 不重复上报 |
| `DEFERRED` | 已决策：以后改，不在本次范围 | 不重复上报 |
| `WONTFIX` | 已决策：明确不改，理由见备注 | 不重复上报 |
| `RESOLVED` | 已修复 | 保留记录，待清理 |

## A. 同值不同域 —— 不可盲目常数化 ⚠️

> **本类是本台账的核心价值所在。** 这些字面量的值与某个既有常量完全相同，看起来是「该用常量的魔术字符串」，但语义属于**另一个取值域**。机械替换不会报错、测试也照过，却会埋下语义错配。

| ID | 位置 | 现象 | 为何不能套常量 | 状态 |
|---|---|---|---|---|
| KI-001 | `miniprogram/pages/my-posts/my-posts.wxml` 的 `data-value="normal"`（4 处） | 同一字面量同时服务于 `editCondition` 与 `editUrgency` 两组选项 | 分别属**成色词汇** {like-new, normal, worn} 与**紧急度词汇** {normal, urgent}，都不是 `DamageType` | `OPEN` |
| KI-002 | `admin/src/views/ContentView.vue` 的 `publishMode`（15 处） | `publishMode === 'lend' / 'wanted' / 'help'` | **小写**页面本地词汇，与 `POST_TYPE` 的**大写**值不同域，套用会大小写错配 | `OPEN` |
| KI-003 | `AdminService.mapCondition` 的 `case "normal"` | 与 `DamageType.NORMAL` 同值 | 实为成色词汇 {like-new, normal, worn} 的一员，此处 `normal` 意为"正常使用痕迹" | `OPEN` |
| KI-004 | `AdminService` 的 `statusTab` / `effectiveTab` 页签判定（`case "completed"`、`"pending".equals(effectiveTab)`、`"moderation".equals(...)`） | 与 `BizStatus.COMPLETED` / `BizStatus.PENDING` 同值 | 实为 **UI 页签域**（moderation / pending / showing / progressing / completed / violation / all），与 `BizStatus` 不同域，同段 `"moderation"` 亦为字面量 | `OPEN` |
| KI-005 | `AdminService` 的 `"admin".equals(moderatedBy)`（2 处） | 与 `UserType.ADMIN` 同值 | 属**审核来源域** {ai, admin}，语义是「已人工复核」而非用户类型 | `OPEN` |
| KI-006 | `DataInitializer` 的 `findByUsername("admin")` / `.username("admin")` | 与 `UserType.ADMIN` 同值 | 是**用户名**字面量，不是 userType | `OPEN` |
| KI-007 | `AdminService` 的 `"borrowing"` / `"helping"` | 无对应常量类 | 代码注释已标明「兼容存量数据旧值（迁移后不再出现，兜底）」，属有意保留 | `WONTFIX` |
| KI-019 | 后端 `NotificationService` 的 `msg.setType("notification")`；C端 `service-notice.js` 的 `msg.type === 'notification'` | 与 `NotificationType.NOTIFICATION` 同值 | 属 **WebSocket 信封类型域**（同域值还有 `"chat_message"` / `"chat_recall"`）。后端与 C端各有一处，**两处都必须保留字面量**。根治方案是新建 `websocket/WsMessageType`（code-standards §4.12 建议），属设计决策 | `OPEN` |
| KI-020 | `AdminService` 的 `kpi("idle", …)` / `kpi("help", …)` | 与 `ContentType.IDLE` / `HELP` 同值 | 属 **DashboardKpi.key 域**（idle / help / pub / mau，见 B端 `api/admin.ts` 的 `DashboardKpi` 类型），同处 `"pub"` / `"mau"` 亦为字面量。根治方案是新建 KPI key 常量类 | `OPEN` |
