# 已知问题台账

> **用途**：登记「已发现、但尚未决策修改」的问题，避免每次质量审查重复发现、重复讨论、重复踩坑。
>
> **本文件存在的原因**：一次三端代码规范清理中，多项问题看似「魔术字符串」却因**同值不同域**而不可机械替换——盲目套用常量会静默改变语义。这类判断每次审查都要重新推理一遍，因此固化到本文件。

## 使用约定

| 角色 | 行为 |
|---|---|
| **quality-review** | **Step 0** 启动时先读本文件；命中已登记项（状态为 `OPEN` / `DEFERRED` / `WONTFIX`）时**不再作为新发现上报**，报告中以一行「已登记 KI-xxx」带过 |
| **quality-review** | 审查结束回写：用户决策「暂不改」→ 追加登记为 `OPEN`；用户决策「改」→ 修复后置为 `RESOLVED` |
| **人工** | 可直接编辑本文件，与 Claude 共用同一份事实 |

**匹配方式**：按「位置 + 现象」描述匹配，**不按行号**（行号会随改动漂移）。
**清理时机**：`RESOLVED` 项保留至下一次全量审查时删除。

### 状态取值

| 状态 | 含义 | 审查时行为 |
|---|---|---|
| `OPEN` | 已确认存在，尚未决策是否修改 | 不重复上报 |
| `TODO` | 已确认要做、尚未排期的**功能需求**（见 E 类） | 不重复上报 |
| `DEFERRED` | 已决策：以后改，不在本次范围 | 不重复上报 |
| `WONTFIX` | 已决策：明确不改，理由见备注 | 不重复上报 |
| `RESOLVED` | 已修复 | 保留记录，待清理 |

## A. 同值不同域 —— 不可盲目常数化 ⚠️

> **本类是本台账的核心价值所在。** 这些字面量的值与某个既有常量完全相同，看起来是「该用常量的魔术字符串」，但语义属于**另一个取值域**。机械替换不会报错、测试也照过，却会埋下语义错配。

### 技术调研结论（2026-09-13）

> 记录下来主要是为了**避免下次照搬网上的错误写法**。调研已排除一条看似可行实则失效的路线。

**⚠️ `onBackPress` 不是微信原生 API。** 查证结果：微信官方 Page 类型定义（DefinitelyTyped `lib.wx.page.d.ts`）与官方路由文档中**均无**该生命周期，它是 **uni-app 的框架抽象**。网上不少「小程序拦截返回」的文章混用了 uni-app 写法——在本项目直接照抄会**静默失效**（未知的 Page 配置键被忽略，不报错），造成「以为修好了」的假象。

**官方机制是 [`<page-container>`](https://developers.weixin.qq.com/miniprogram/dev/component/page-container.html) 组件**（基础库 2.16.0+）：
- `show=true` 时自动拦截**右滑手势 / 安卓物理返回键 / `navigateBack` 调用**，拦截效果是**关闭容器本身**，而非退出页面
- 拦截后容器自动置 `show=false`，之后不再拦截
- 相关事件：`bind:beforeleave` / `bind:afterleave` / `bind:clickoverlay`

**关键约束**：**每个页面最多只有 1 个 `page-container`**。这直接卡住 `my-posts`——它有 5 个底部弹层（编辑 / 审批 / 进行中 / 已完成 / 抽屉），无法各配一个容器。

**已定方案**（用户 2026-09-13 确认）：`my-posts` 的 5 个弹层**合并进单个 `page-container`**——由一个派生状态（任一弹层开启）驱动 `show`，内容按当前弹层类型条件渲染；`bind:beforeleave` 中关闭当前开启的那个。

**`my-posts` 的 10 个覆盖层清单**（供实现时参考）：
- 底部弹层 5 个：`showEditSheet`、`showApprovalSheet`、`showProgressSheet`、`showCompletedSheet`、`showDrawer`
- 确认弹窗 5 个：`showConfirmAlert`、`showReturnConfirmAlert`、`showOverdueTipAlert`、`showSaveConfirmAlert`、`showOfflineAlert`

**实现要求**：属 WXML 结构级改动（弹层 markup 需移入同一容器），**必须真机验证**——模拟器与真机的手势返回行为可能不一致。
